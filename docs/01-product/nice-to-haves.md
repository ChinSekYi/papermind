# Nice to Haves

## Comparison rules
- Only compare papers on the same decision axis.
- Example: a Transformer architecture paper vs an MLOps paper is not a direct comparison.

Use this rule:
- Same problem or job-to-be-done.
- Similar evaluation context (dataset, task, metric) if performance comparison is needed.
- Same decision type:
	- Model-method decision (for example, Transformer variants)
	- System-design decision (for example, RAG architecture choices)
	- Ops-tooling decision (for example, experiment tracking platforms)

## If papers are different
- Do not force a benchmark comparison.
- Use complementary mapping:
	- Paper A helps with model quality.
	- Paper B helps with production reliability.
	- Together they form an end-to-end stack.

## MVP gate
- Detect paper type and topic first.
- If mismatch is high, show: "Not directly comparable."
- Offer alternative output: "Relationship summary" instead of "Winner table."
